# WordRoot 单词学习 MVP

一个强调例句回忆与词根词缀分析的本地单词学习程序。前端使用原生 HTML、CSS 和 JavaScript，后端使用 Python 标准库，不需要安装第三方依赖。

## 启动

最简单的方式是双击 `start_wordroot.bat`，程序会启动本机服务器并打开浏览器。

也可以手动启动：

1. 如需生成新词，将 `.env.example` 复制为 `.env`，填写 `DEEPSEEK_API_KEY`。
2. 在项目目录运行：

   ```powershell
   python server.py
   ```

3. 在浏览器打开 <http://127.0.0.1:8000>。

网页中的“测试 API 连接”可以单独验证密钥、账户余额及网络连接。DeepSeek 配置会在每次请求前重新读取，因此修改 `.env` 后无需重启程序。

网页右上角的“关闭程序”会保存现有数据并停止本机服务器。浏览器出于安全策略可能拒绝自动关闭手动打开的标签页，此时页面会显示关闭提示，可以手动关闭标签页。

项目已内置 `predict` 示例卡片，可以在不配置 DeepSeek 的情况下体验完整学习流程。

## 学习规则

- 先显示目标词及其全部例句，用户自行输入答案。
- 一个真正独立的词义对应一个释义项和一个例句；近义改写合并，不同用法拆分。
- 揭示音标、词根词缀分析和全部释义后，用户必须为每项明确选择“答对了”或“没答对”。
- 只有全部释义均答对，本次记录才是 `correct: true`。
- 答错为 `again`，该词立即追加到当前队列末尾，可不限次数重复。
- 进度只计算已经答对的独立单词，重试不会扩大原计划的单词总数。
- 第一次答对为 `hard`；连续2、3、4次答对依次为 `good`、`easy`、`know_well`。
- `hard`、`good`、`easy` 分别在1、3、7天后复习。
- 用户可以手动设为 `know_well`，但不能手动指定其他反馈。
- 所有到期和逾期项目都会进入复习队列。

## 数据与数据库兼容

当前数据保存在 `VocabularyDatabase` 中：

- `words/*.json`：单词、音标、构词分析、释义和例句。
- `learning_state/*.json`：逐次学习记录、当前反馈及下次复习时间。
- `LearningPlan.json`：当前新词学习会话与重试队列。
- `ReviewPlan.json`：复习索引及当前复习会话。

业务逻辑只依赖 `storage.py` 中的 `VocabularyRepository` 抽象接口。未来迁移 SQLite、PostgreSQL 等数据库时，可以新增一个仓储实现并在 `server.py` 中替换实例，无需修改前端、复习算法和 HTTP 接口。

每个 JSON 都带有 `schema_version`，方便后续进行数据迁移。

## 分享给其他人

将整个项目文件夹复制或压缩后交给对方，而不是只发送 `127.0.0.1:8000` 链接。`127.0.0.1` 永远指向正在使用浏览器的那台电脑，因此对方运行 `start_wordroot.bat` 后，连接的是对方自己的电脑。

分享前请删除 `.env`，不要泄露自己的 DeepSeek 密钥。接收者应复制 `.env.example` 为 `.env`，并填写自己的密钥。学习数据也保存在接收者自己的 `VocabularyDatabase` 文件夹中，不会传回原作者电脑。

项目默认只监听 `127.0.0.1`，局域网或互联网中的其他设备不能直接访问，符合“每人使用自己的本地服务”的设计。

双击 `create_share_package.bat` 可以生成 `WordRoot-share.zip`。该压缩包会自动排除 `.env` 和个人学习记录，同时保留词库内容并为接收者建立全新的学习状态。

## DeepSeek 生成

点击首页“生成10个 CET-6 新词”时，后端会：

1. 排除词库已有单词；
2. 请求10个不同的 CET-6 单词；
3. 检查音标、词根词缀、释义和例句是否完整；
4. 全部通过后才写入词库并创建学习计划。

API 密钥只由后端读取，不会发送到浏览器。

生成失败时，首页会保留具体原因，例如密钥无效、余额不足、请求频繁、输出截断或返回字段不完整，不再只显示短暂提示。
